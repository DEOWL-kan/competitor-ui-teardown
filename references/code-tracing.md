# Android 定向代码追踪

先写问题，例如“保存按钮最终写本地还是发请求”，再从 Manifest 入口、UI 文案、资源 ID 缩小范围。优先使用用户提供的合法源码；JADX 是可选静态辅助，不是完整源码恢复保证。

1. 运行 apk_profile 和 feature_probe，覆盖用户提供的每个 split。记录缺失包、哈希、版本与可读边界。
2. 检查 `jadx --version`；未安装只报告 unavailable，未经授权不安装。每个输入包使用仓库外新的独立输出目录；不要覆盖或合并已有反编译输出。
3. `jadx -d /scratch/new-base-output /scratch/base.apk`。保存实际命令、工具版本、退出码、日志和输出文件哈希。退出码 0 仍需检查 ERROR 日志及预期类/方法是否真的产生；本项目损坏 DEX 样本在 JADX 1.5.6 中恰好出现了错误日志但返回 0 的情况。输出与反编译行号只对这次产物有效。
4. 用 `rg -n '明确文案|资源名|方法名' /scratch/new-base-output/sources` 找引用；不要将第一个命中当成 UI 归属。
5. 阅读入口处理、参数构造、调用和状态更新上下文，一到两级追踪足够回答问题就停。记录每一步所在类/方法/文件/行，以及是否有运行证据。
6. 同名 SDK 文案、未调用分支、反射、动态类、JNI/WebView 桥接处检查反例。没有跨边界证据就停；不能根据 native 方法名补写实现。

Flutter 的 DEX 只覆盖 Android 宿主/插件，Dart AOT 业务代码不恢复。RN 明文 bundle 可以读；Hermes 字节码只记录识别线索与缺口。混淆、重命名、反编译警告与失败逐项保留。包名前缀只是归属线索，不证明第一方。

成功交付应是具体链路：入口→方法→下游操作，并有至少一个替代解释、边界与反证。结论写“此哈希包的此方法包含此调用”；“用户实际点击后执行成功”需要运行观察。缺真机不妨碍静态画像，但不能达到完整运行验收。
